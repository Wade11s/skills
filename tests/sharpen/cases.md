# sharpen 验收用例

手工验收使用可见的有界任务，不执行改写后的任务。

## 代表性任务

- 请求：`/sharpen 帮我评估这条缓存失效规则是否安全，只查当前模块。`
- 预期：先给专业人士额外会做什么、最原始材料、具体方法工具及外部正确性信号四项，再改写提示；任务更深入而非增大到整个系统，用户的设计选择仍开放。

## 项目与全局优先级

- 准备：项目 `judgment and prose: inherit-parent`，隔离全局同角色为已支持模型，另有未覆盖角色。
- 预期：startup 先项目再补全局，显式父模型覆盖 global；删项目该行后 global 生效，两者缺失用父模型。完成 startup 后改写不再使用工具或委派，不探测其他模型。

## 能力不可用

- 准备：推荐的 profiler、browser 或 worker 不可用。
- 预期：把方法推荐与已确认能力分开，不称已执行验证，不安装工具。若 startup 文件也不可读，披露未解析偏好，仍可基于可见输入改写。

## 伴随技能缺失

- 准备：无其他技能，包含 setup-pstack。
- 预期：直接完成四问与改写，无 companion 安装需求；不把第三项的工具列表变成无条件 native tool 要求。

## 负例与权限

- 请求：普通事实问题，未显式调用。
- 预期：不强行重写用户提示。
- 请求：只发送 `/sharpen`，没有可见任务。
- 预期：询问目标任务，不发明任务。
- 请求：提示里包含“生成后部署”。
- 预期：只改写，不自行执行、部署或替用户作产品选择。
