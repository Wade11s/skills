# setup-pstack 验收用例

## 首次设置与取消

- 准备：在真实小项目中显式加载当前检出的 setup-pstack；使用隔离 home，项目/全局均无配置，保留文件树快照。
- 请求：配置一下 pstack 的模型。
- 预期：先确定业务项目根，给出 project-level 和 global-level 及各自绝对目标路径，等待选择。不能从技能源码目录猜业务项目。
- 边界：用户未选作用域或取消时，不创建目录或文件，不自动安装提供商、技能或验证依赖。

## 项目级写入与逐角色继承

- 准备：隔离全局文件含 how explorer 与 why synthesizer 的已确认模型；项目文件不存在。
- 请求：project-level；仅把 how explorer 设为 auto，预算 small；这是对这些精确内容的写入确认，不需要生成验证技能。
- 预期：只写项目文件；how explorer 取项目 auto，why synthesizer 仍取全局；读回并说明生效来源和预算。
- 边界：全局文件逐字节不变；不添加未确认的角色，不把预算拼进模型 ID。

## 全局级编辑与项目遮蔽

- 准备：项目 how explorer 为 auto，全局为其他已确认模型；两份均有自定义项。
- 请求：global-level，更改全局 how explorer 的模型，保留其余全局角色。
- 预期：全局编辑表不复制项目值；确认前列出被项目遮蔽的角色。只写全局，当前项目 how explorer 仍是 auto。
- 边界：项目文件不变；不声称全局更改会覆盖所有项目。

## 重跑、移除和面板

- 准备：项目自定义角色及全局 arena runners 列表。
- 请求：重跑 setup，保留自定义模型，把预算改成 medium；项目 arena runners 设成三个条目，其中两个 inherit-parent。
- 预期：保留模型族；列表整体替换而非合并；重复别名仍是三个尝试，不能宣称模型族多样性。再次相同操作得到相同文件。
- 后续：移除项目的 arena runners 行，应恢复整个全局列表，而不是删全局行。
- 带分隔符的已确认选择器：`provider/model[effort=high,speed=fast]` 必须保持一个模型；任意含逗号的 ID 使用 JSON 字符串或面板 JSON 数组，不能增加执行席位。

## 缺失或无效能力

- 准备：模型枚举和每 worker 模型选择均不可用。
- 请求：设置模型。
- 预期：给出 parent/auto 或请求用户提供已确认 ID，不能硬编码供应商品牌模型；不花费调用配额探测可用性。
- 准备：文件含空值、重复角色、不可读路径或未知旧角色。
- 预期：指出具体问题，未知项在丢弃前确认；无效配置不能静默回退或覆盖。
- 预算近似格式：项目写成 `#budget: small (medium)`，全局预算为 `large (xhigh)`。只读解析器必须在 JSON warnings 中报告项目路径、行号和规范写法，并明确被忽略后继承的预算；Agent 在使用继承预算前展示该告警，不自动改写任一配置。普通的预算说明注释不应触发告警。

## 子目录与跨工作树

- 准备：项目根与临时子目录各有不同配置，任务显式指定原项目根。
- 请求：设置原项目模型，并委派一次小检查。
- 预期：原项目根决定配置；子代理收到根、来源和有效偏好，不因工作目录变更而重选作用域。

## 不应使用的场景

- 请求：解释如何配置 pstack，但不要修改文件。
- 预期：仅回答和展示选择，不落盘、不生成验证技能。

## 自动化边界

`test_models.py` 验证只读解析器的实际文件读取、继承和错误行为，不覆盖模型枚举、用户确认或代理执行。交互用例必须按 tests/README.md 在干净会话验证。
