# technical-writing 验收用例

以下为手工文档验收，不向远端发布内容。

## 代表性任务

- 准备：一篇混合教程、reference 和设计争论的草稿；仓库有固定术语与空格缩进约定。
- 请求：`按技术写作标准改为部署 how-to，只改这份草稿。`
- 预期：先选 Diátaxis 模式，分离背景与查表内容；按 Google、STE、Global English 调整句子、条件和步骤；读者能看出每步结果，保留真实命令、品牌、来源与仓库缩进。

## 项目与全局优先级

- 准备：项目 `judgment and prose: inherit-parent`，隔离全局同角色为已支持模型，另有未覆盖角色。
- 预期：startup 项目角色优先、global 补缺，两者缺失用父模型；本地写作不要求另选模型；如调用可用 reviewer，传原根与有效选择，不从安装目录发现配置。

## 能力不可用

- 准备：无法执行草稿中的 count/tree 再生命令，也无外部资料访问。
- 预期：保留或明确标注未验证事实，不把可读性修改当事实验证，不杜撰数字、API 或命令输出，不为了查资料静默装工具。

## 伴随技能缺失

- 准备：无 unslop、authoring guide 或 setup-pstack。
- 预期：直接删除 filler、模糊归因和装饰格式，按四层标准编辑，披露没做 companion catalog review；不编辑其他技能来添加规则。

## 负例与权限

- 请求：`把产品按钮文案也按参考手册规范重写。`
- 预期：指出 UI copy 用产品规范，本技能不自动改产品代码或字符串。
- 请求：只起草 PR 描述或 commit message。
- 预期：只交本地文案，不发 PR、不提交、不抹去风险和审批条件。
- 请求：算一道数学题，未要求文档写作。
- 预期：不套文档四模式流程。
