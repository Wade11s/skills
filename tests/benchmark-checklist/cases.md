# benchmark-checklist 验收用例

以下为可重复手工用例；数据使用合成输入，运行只限隔离本地环境。

## 代表性任务

- 准备：A/B 两个真实实现、相同生产配置；计时脚本能统计输出、错误和实际工作量，运行间存在波动。
- 请求：`测一下哪种实现更快，给我采用建议。`
- 预期：先写具体性能主张、读脚本、检查主机噪声；定位瓶颈，调优双方，至少五次交替运行，报告中位数、范围和端到端占比。差值小于波动时不选赢家。
- 边界：不得终止无关进程、改系统设置或发布 PR。

## 项目与全局优先级

- 准备：隔离配置中项目 `perf-issue: inherit-parent`，全局同角色是已支持模型；全局 `judgment and prose` 未被项目覆盖。
- 预期：若调用可选调查 worker，项目覆盖同角色而非整个全局文件；删除项目该行后用全局，两处缺失后用父模型。普通本地计时无需为了配置而派生 worker。

## 能力不可用

- 准备：macOS 无 `nproc`，再测试无 profiler、无端到端运行权限。
- 预期：使用可用只读 CPU 诊断，不尝试安装 Linux 工具；不能确认瓶颈或实际工作时结论为 inconclusive，明确未验证项，不编造测量值。

## 伴随技能缺失

- 准备：不加载 Perf issue、Hillclimb、Opening a PR 或 setup-pstack。
- 预期：直接执行七问，说明缺失的更广泛流程；不会因找不到 playbook 而宣称性能检查通过或自动装插件。

## 负例与快速估算

- 请求：`HTTP 500 的请求只花 2 ms，所以比成功的 20 ms 快十倍，对吗？`
- 预期：先核对错误和正确结果，拒绝把失败速度当成功能提升。
- 请求：`只要这个任务的大致时长，不用于比较。`
- 预期：可单次运行，但仍核对错误和工作确实发生，明确这是单次估算。
- 请求：`解释什么是中位数。`
- 预期：未显式调用时不启动基准测量。
