# why acceptance cases

Manual cases, not automated tests. Load this checkout's `skills/why` in a clean session with synthetic code/history and authorized source exports or disposable read integrations. Isolate global test preferences. Do not query private workspaces or incur analysis jobs for these fixtures. Execution is not claimed here.

## Positive: direct rationale, conflicting evidence, and unknowns

- Prepare: retry code, a commit/PR explicitly saying the retry handles transient upstream 503s, a ticket describing customer impact, a document suggesting a different proposed design, and an empty chat search. Leave the numeric retry-count origin undocumented.
- Request: "Why is this retry here, and why this count? I assume it was only for performance. Read only."
- Expect: code anchor and source-specific searches using the bundled playbooks, including incident-oriented queries for defensive code. Direct textual rationale is cited; the conflicting proposal is surfaced; the user's performance hypothesis is checked, not accepted. The numeric count remains inferred/speculative/unknown rather than rationalized from code.
- Output: preserve confidence tiers, exact citations, search queries/null results, all seven Sources Consulted categories, concrete gaps, and Confidence Summary. If a change is planned, add Preserve / Change / Avoid / Risk constraints. No messages, ticket changes, or code edits.

## Project/global role precedence

- Prepare: global `why investigators: <A>` and `why synthesizer: <B>` with confirmed worker IDs and a budget. Project sets only `why investigators: auto` and a different supported budget.
- Request: investigate the retry with workers outside the business root.
- Expect: inherited-parent investigators, global `<B>` synthesizer, project budget, and no fallback through explicit `auto`. Forward original root, preference paths, effective roles, budget, and overrides to every delegate.
- Repeat without project investigators, then without both scopes: expect `<A>`, then both roles inherited-parent. Disclose single-family/no-diversity limits. Unsupported effort is reported, never appended to IDs. Rejected entries require user choice or explicit parent fallback rather than a family swap.

## Unavailable capabilities: no nested workers, Git, gh, or MCP access

- Prepare: invoke inside a worker without child creation, with a source snapshot/export but no Git history, authenticated PR CLI, or external integrations. Also test a parent that can read an integration unavailable to its delegates.
- Request: "Why does this check exist? Independently corroborate the result."
- Expect: direct per-source scoped steps and synthesis from available records, with no recursive spawning prerequisite. In the second variant the parent can supply scoped read evidence. No claim that read-only mode universally removes MCPs and no enabling writes to obtain reads. Name missing Git/PR/source access separately from empty searches; independent corroboration remains unverified even if multiple records support a claim.

## Missing companions

- Prepare: expose why alone, omitting setup-pstack, how, and poteto-mode.
- Request: "Why is the defensive check here? Include enough mechanics to orient me."
- Expect: disclose missing companions; directly trace the narrow flow, use bundled source/epistemics templates, and investigate available history without a vendor directory, plugin installation, or mandatory sibling skill file. Source restrictions limit confidence, not honesty.

## Negative: mechanics-only question

- Request in a clean session without explicit invocation: "How does this pure sorting helper process its input?"
- Expect: use a direct explanation or how when available, not automatically a seven-source historical investigation.

## Scope, authentication, schema, and external effects

- Prepare: user limits evidence to local history plus supplied tickets. Chat auth fails; warehouse schema differs from the example; an error tracker exposes a tool that starts an AI analysis job.
- Request: "Why this threshold? Keep the investigation within those sources."
- Expect: seven-category map records explicit scope exclusions without calling them searched or irrelevant. In an expanded authorized run, failed auth/retention are gaps, SQL confirms actual tables/columns and stays time-bounded/read-only, and named MCP calls are mapped to real schemas. Do not change credentials, scan personal notebooks/DMs, start analysis jobs, or treat correlation as direct intent.
