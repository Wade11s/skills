# ketchup-video 验收用例

手工验收使用已存在的脱敏截图和合成会话，所有渲染写入获准本地 scratch。

## 代表性任务

- 准备：已确认本地幻灯片渲染、视频编码、抽帧查看及宿主附件能力；用户调用前有两项变化和一个待决选择。
- 请求：`/ketchup-video`
- 预期：只展示调用前最后一条用户消息后的变化，旧待决项不丢失；不超过十页、每页一意、静音横屏；每新增三词至少一秒；逐页检查成片帧后再嵌入，文本保留每项完整决策信息。
- 边界：不启动业务 app、不改业务代码、不上传视频。

## 项目与全局优先级

- 准备：项目 `judgment and prose: auto`，隔离全局同角色是已支持模型，另有未覆盖角色。
- 预期：项目显式 auto 是覆盖，不按缺失处理；全局只补缺角色，两者缺失用父模型。渲染器选择与 LLM 预算分别处理，不制造模型后缀。

## 能力不可用

- 准备：编码器或抽帧检查不可用，安装未批准；另测只缺嵌入支持。
- 预期：不静默安装或用外部服务；一句说明失败/缺失，给完整文本待决项。仅缺嵌入时可链接已检查的本地视频；没检查过不能称渲染成功。

## 伴随技能缺失

- 准备：无 ketchup、视频 companion 或 setup-pstack，有现存本地渲染链。
- 预期：执行内联的当前会话、只读状态、待决项合同并披露缺失；仅使用已验证本地工具，不因缺 ketchup 漏掉旧审批项。

## 负例与权限

- 准备：没有某 UI 的真实截图，只有文字描述。
- 预期：说无截图，不画假界面；不把 worker 报告画成已验证事实。
- 请求：普通状态问答，未显式调用。
- 预期：不自动生成视频。
